# MMS Somali ASR fine-tune

Fine-tune of [`facebook/mms-1b-all`](https://huggingface.co/facebook/mms-1b-all) (Somali adapter `som`) for
Somali speech recognition. It serves as the Somali ASR and as the judge for the GLM-4-Voice resynthesis checks.

Published (private): [`lewenberg/mms-1b-somali`](https://huggingface.co/lewenberg/mms-1b-somali). The tag `base` is
the untouched `facebook/mms-1b-all`; the tag `asr_mms` is this fine-tune.

## Is it a full fine-tune?

Yes, for practical purposes. `configs/asr_mms.yaml` uses `mode: full`, and the training log reports
**960,531,913 trainable parameters out of ~965M**.

| Part of MMS-1b-all | Trained? |
|---|---|
| 48 transformer layers (the bulk of the 1B params) | ✅ |
| Somali adapter layers (`som`) | ✅ (saved as `adapter.som.safetensors`) |
| CTC output head (73-symbol Somali vocab) | ✅ |
| CNN feature encoder (~4M params, raw waveform → features) | ❌ frozen |

Freezing the CNN feature encoder is the standard wav2vec2/MMS recipe: those low-level acoustic filters are
already good and language-agnostic, and training them on ~62 h mostly adds instability.

The alternative, `mode: adapter`, trains only the Somali adapter and head (~2M params), with a learning rate
of ~1e-3. It wasn't used: with 62 h of data the full fine-tune is the stronger choice.

## Data

| Source | Clips | Hours | Notes |
|---|---|---|---|
| Somali TV/podcast segments (`prepare_asr`) | 69,804 | 57.2 | diarized segments; transcripts machine-generated by `microsoft/mai-transcribe-2` |
| [`IbrahimDayax/somali-combined-asr-stt-dataset`](https://huggingface.co/datasets/IbrahimDayax/somali-combined-asr-stt-dataset) (`prepare_asr_ext`) | 6,477 | 4.8 | read + synthetic TTS Somali; revision pinned in the config |
| **Train total** | **76,279** | **62.0** | clips ≤ 20 s |

Held-out splits are whole episodes (deterministic hash), so no episode appears in both train and test.
Text normalization: NFKC, lowercase, keep `a-z 0-9 ' -`, no punctuation, which matches what the stock MMS
Somali head emits.

## Training

`configs/asr_mms.yaml`: 3 epochs (7,152 steps), batch 16 × grad-accum 2, lr 3e-5, 500 warmup steps, linear
decay, bf16, gradient checkpointing, length-grouped batches. Eval every 1,000 steps on 1,500 val clips, and
the best-CER checkpoint is kept. It took ~65 min on one RTX PRO 6000 Blackwell (96 GB).

## Results

CER / WER, lower is better:

| Test set | Stock `mms-1b-all` (som) | **Fine-tuned** | Relative CER drop |
|---|---|---|---|
| Our test episodes (1,543 clips) | 0.341 / 0.788 | **0.208 / 0.604** | −39% |
| Our val episodes (2,622 clips) | 0.343 / 0.796 | **0.204 / 0.596** | −41% |
| IbrahimDayax test (795 clips) | 0.100 / 0.396 | **0.056 / 0.226** | −44% |

Our own test labels are machine transcripts; `microsoft/mai-transcribe-2` has no Somali support and
auto-detects other languages. Part of the remaining error on our episodes is therefore label noise. The
IbrahimDayax test set is the cleaner measure.

## Reproduce

```bash
finetune/run.sh prepare_asr        # Somali segments -> asr/{train,val,test}
finetune/run.sh prepare_asr_ext    # IbrahimDayax dataset -> asr/ext_{train,val,test}
finetune/run.sh eval_asr_stock     # baseline
finetune/run.sh train_asr          # full fine-tune -> $SO_WORK/runs/asr_mms/final
finetune/run.sh eval_asr_ft
finetune/run.sh publish_asr        # private HF repo: base commit, then fine-tune
```

Code: `finetune/prepare_asr.py`, `prepare_asr_ext.py`, `train_asr.py`, `eval_asr.py`, `publish_hf.py`.
